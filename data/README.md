# `data/` — Dataset

## Overview

The dataset consists of **15 subjects**, each instrumented with two wearable devices, recorded across three conditions:

- A **chest-worn sensor band**: ECG, EDA, EMG, respiration, skin temperature, and 3-axis acceleration, sampled at 100 Hz.
- A **wrist-worn sensor**: blood volume pulse (BVP), EDA, skin temperature, and 3-axis acceleration, at typical smartwatch rates (BVP 64 Hz, EDA/temperature 4 Hz, acceleration 32 Hz).
- Conditions: **baseline**, **stress**, and **amusement**.

Each subject shows realistic inter-subject variability (different resting heart rates, baseline skin conductance levels, and individual differences in how strongly each person's physiology reacts to a given condition) and genuine physiological drift within each condition, so the resulting classification task is a meaningful, non-trivial one — not a synthetic shortcut. See `docs/REPORT.md` Section 2 for the full rationale behind these design choices.

> **A note on the data.** The dataset used in this project was manually created rather than collected from real hardware, using a physiologically-motivated signal model (`src/synthetic_data.py`) designed to reproduce realistic autonomic response patterns for each condition (e.g. higher heart rate and lower HRV under stress, elevated EDA under stress, faster/shallower breathing under stress). This made it possible to fully control ground-truth conditions and keep the entire pipeline reproducible end-to-end.

## Folder contents

```
data/
├── raw/          — one .pkl file per subject (generated by src/synthetic_data.py)
└── processed/    — feature tables (generated by src/feature_extraction.py and src/modeling.py)
```

Both folders are populated by running the pipeline scripts (see the main [README](../README.md#installation--how-to-run)) and are gitignored — nothing here needs to be committed, only regenerated.

### `data/raw/{subject_id}_synthetic.pkl`

One file per subject, each a dict with:

| Key | Description |
|---|---|
| `subject_id` | e.g. `"S2"` |
| `chest` | dict of 8 arrays: `ECG`, `EDA`, `EMG`, `RESP`, `TEMP`, `ACC_x`, `ACC_y`, `ACC_z` (100 Hz, full session length) |
| `chest_label` | integer array, same length as `chest` arrays: 0=transient, 1=baseline, 2=stress, 3=amusement |
| `chest_fs` | 100 |
| `wrist` | dict of 6 arrays: `BVP`, `EDA`, `TEMP`, `ACC_x`, `ACC_y`, `ACC_z`, each at its own native rate |
| `wrist_fs` | dict of per-signal sampling rates: `{"BVP": 64, "EDA": 4, "TEMP": 4, "ACC": 32}` |
| `segment_times` | dict of `(start_sec, end_sec)` per condition, for reference/debugging |

15 subjects (`S2`–`S17`, skipping `S1`/`S12`), each with a ~1110-second session (8 min baseline + 6 min stress + 4 min amusement + two 15s transient gaps between conditions).

### `data/processed/`

- **`features.csv`** — one row per 60-second window (495 rows total), columns = `subject_id`, `label`, + 55 feature columns (see `src/README.md` for the feature list and `src/feature_extraction.py` for the full computation).
- **`features_normalized.csv`** — the same table after per-subject baseline-referenced z-scoring (see `src/modeling.py::normalize_per_subject_baseline`), used as the model input.

## Regenerating

```bash
python3 src/synthetic_data.py       # writes data/raw/*.pkl
python3 src/feature_extraction.py   # writes data/processed/features.csv
```

`features_normalized.csv` is written automatically the first time `python3 src/modeling.py` runs.

## Using your own sensor data instead

`src/preprocessing.py::load_subject` looks for `data/raw/{subject_id}_synthetic.pkl` first and falls back to `data/raw/{subject_id}.pkl` in the same schema (`{"signal": {"chest": {...}, "wrist": {...}}, "label": array}`) if present — drop in real sensor recordings in that format and the rest of the pipeline runs unchanged.
